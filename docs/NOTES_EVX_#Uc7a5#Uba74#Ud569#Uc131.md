## EVX → 장면 합성 (WMP 배경 + WPC 스프라이트)  — C++ 이식 / 검증
출처: py/evx_vm.py, wmp_render.py, wpc_play.py, wpc_overlay.py 및 C++ core (evx.*, wmp.*, wpc.*, scene.*)

### 1. EVX 파일 구조 (헤더 필드 위치 정정)
    +0 'EVX0'  +4 u32 크기  +8 u16 entry(main 시작)  +10 u16 strbase(=0x10)  +12 u32 0
    문자열(cp949, NUL 종료) 0x10 ~ code_start, 이어서 서브루틴, main 은 entry 에서 시작
    * entry 는 +8 이다 (+10 이 아님). +10 은 항상 0x10.
    * code_start 찾기: 0x10 ~ entry 사이에서 "그 지점부터 선형 스윕으로 파일 끝까지 유효 op 만 만나고,
      정확히 파일 끝에 도달하며, entry 가 명령 경계에 걸리는" 가장 작은 시작점. 143/143 성공.
    * 명령 길이: u16 인자 = 01 0c 10 11 12 (3바이트), u8 인자 = 03 05 07 09 0a (2바이트), 나머지 1바이트.
      유효 op 집합 = opstats.json 키 125종 + 0xff.
    * EVX 는 FPA 인덱스 오프셋 12바이트 앞에서 ABP_ 가 시작한다.

### 2. 스크립트가 화면에 요구하는 것 (VM 트레이스)
    BACKGROUND  op 6f (또는 8b 모드 2):  마지막 인자 = M 번호 (이미 최종값, 래퍼 규칙 적용 후)
    SPRITES     op 5f:                   인자 = P 번호 (65535 = 없음 -> s16 -1)
    PORTRAIT    op 3e:                   slot, mode, B###### (hi, lo)
    PICTURE     op 85:                   x, y, id
    * 143개 스크립트 중 배경을 요청하는 것 97개. 스프라이트까지 요청하는 것은 5개
      (CNTST0/1/2 -> P142/143/144, PCCTEST -> P001, TEST4 -> P142).
    * EvxVm::events 에 구조화해서 기록 (텍스트 log 는 그대로 -> 143개 트레이스 바이트 동일, 233,243줄).
    * 한계: 대부분의 장면(수업/알바 등)은 입력 대기·계절·점수에 따라 P/M 이 정해져 VM 트레이스만으로는 안 나옴.

### 3. WMP 장면 (wmp_render.frames 이식)
    * 이미지는 24bpp GDT(보통 832x480): x<640 영역이 배경, 640 이후는 부품 시트.
    * 배경 = 시트의 (0,0,640,480). 그룹 1.. 의 단일 rec 그룹 중 (dstx,dsty,w,h) 가 같은 것이 연속하면
      한 애니메이션 오브젝트의 프레임 열, 그 외(rec 2개 이상)는 정적 오버레이.
    * 프레임 수 = 오브젝트별 프레임 수의 최소공배수, 최대 24 (1 이면 정지). 표시 간격 150ms.
    * 색키 = 시트 x>=640 영역(폭<=640 이면 전체)에서 G<=0x0c, R>=0xb0, B>=0xb0 인 가장 많은 색 (동률이면 먼저 나온 색).
      파일마다 다르다. rec 복사는 (page*256+srcx, srcy, w, h) -> (dstx, dsty), 색키 픽셀은 건너뜀.
    * 검증: 141개 장면 첫 프레임 픽셀 동일, 애니메이션 7개 프레임 수 동일.

### 4. 스프라이트(WPC)를 배경 위에 놓는 법
    * 슬롯 위치/애니 오프셋/rect 의 dst 는 전부 반해상도 단위 -> 화면 = 값 x 2, 원점은 화면 (0,0).
    * 즉 640x480 배경 위에 (rect.dst + 슬롯 pos + anim d) x 2 로 그대로 그린다. 별도 보정 없음.
      확인: P001 on M0001(도장), P000 on M0000(교실) 에서 학생·책상이 바닥 원근에 맞음.
    * 그리기 순서: 슬롯 param(0c SETPARAM) 오름차순, 같으면 슬롯 번호 순.
    * 음수 좌표는 픽셀 단위로 클리핑 (파이썬 wpc_overlay 는 x<0 인 스프라이트를 통째로 건너뜀 -> 차이점).

### 5. 뷰어 사용
    <SCRIPT>.EVX SCENE   배경(+스프라이트) 장면. 스크립트가 마지막으로 요청한 M/P.
    <NAME>.WPC PLAY      스프라이트 재생. 중앙 탭 / B 키 = 다음 배경 (없음 -> M0000 -> ... 순환).
                         EVX 에서 짝이 확인된 P 는 그 배경으로 시작.
    pm3_dump scene <game_dir> out.ppm <SCRIPT | P###:M####> [tick]   헤드리스 1프레임 합성

### 5b. 초상화 (WBD, op 3e 의 B######)
    * 구조/렌더는 wbd_render.py 와 동일하게 C++ 이식 (core/pm3/wbd.*). 404개 전부 기본 프레임 RGBA 픽셀 동일,
      타임라인(frame,ticks) 목록 동일. 뷰어는 `<NAME>.WBD` 페이지에서 눈 깜박임 루프(타임라인 2, 없으면 1, 틱 = 33ms).
    * 위치 (EXE 디스어셈블): 초상화 슬롯은 0~3. 슬롯별 변수 X=[0x4A763C+4*slot], Y=[0x4A764C+4*slot], 우선순위 Z=[0x4A765C+4*slot],
      표시 플래그=[0x4A762C+4*slot]. 그리기(0x4311A8 -> 0x43155F)는 rect 마다 화면 위치 = (rec.dst + (2*X-256), rec.dst + 2*Y).
      rec 의 dst/src/w/h 는 배수 없이 픽셀 그대로 (WPC 와 달리 x2 하지 않음).
    * op 3e (0x410B13) 인자: slot, mode(미사용), B hi, B lo -> 0x430DDF(slot, ., hi, lo) 가 스레드로 WBD 로드. 로드 완료 시 X=Y=Z=0, 표시 플래그=1
      (그래서 로드 직후 x=-256 으로 화면 밖 왼쪽).
    * op 4a (0x40C738) = 초상화 이동: 인자(스택 위에서부터) slot, x, y, mode[, 시간].  mode 0: X=x, Y=y 즉시, mode 1: 거리/8 프레임 동안 이동,
      mode 2: 지정 프레임 동안 이동. 어느 모드든 최종값은 (x, y).  (트레이스의 `op_4a(0, 'PS_100.32', ...)` 처럼 문자열처럼 보이는 인자는
      값이 우연히 문자열 오프셋과 같아서 로그가 텍스트로 찍은 것.)
    * op 53/5c/5d -> 0x430D2A(slot, v): Z = 0x80 - clamp(v, 0, 0x80)  (겹침 우선순위).  op 78 -> 0x430D55: 화면 효과 계열(미해독).
    * C++: EvxVm::events 의 Move(op 4a) 로 슬롯 X/Y 를 따라가고(Portrait 로드 시 0 으로 리셋), `EvxSceneInfo::portraits` 에 슬롯 최종 상태를 담는다.
      SCENE 페이지가 이를 그대로 그림. 예: EN101 = M0137 배경, 슬롯1 B447000 @ (240,0) -> 화면 x=224 (결과 이미지가 화면에 자연스럽게 놓임).
    * 한계: 표시 플래그 해제(숨김)와 Z 우선순위, 이동 중 위치, 말할 때 y 흔들림(0x4311A8 의 [ebp-0x14]) 은 미반영.
      EN101 에서 슬롯0(B470000 @160,0) 은 그려지지 않았는데, 스크립트가 숨긴 것인지 슬롯 번호 해석 문제인지 미확정.

### 6. 열린 문제
    * 계절(op_66(3072): 3=겨울 -> 배경 +17, P +32), 시험 시 P+1, 알바 점수별 P 선택 규칙 미반영.
    * 파티클/오버레이 op (11, 15~18, 1b~1d) 시뮬레이션 미구현 (P142~P144 의 정지된 구경꾼).
    * 초상화(op 3e) 의 화면 위치(slot, mode) 미해독.

## TFN 폰트 (FONT22.TFN / FONT24.TFN)

EXE 로더(0x41350E) 분석으로 확정한 구조 (두 파일 모두 1,347,027 바이트):

| 오프셋 | 크기 | 내용 |
|---|---|---|
| 0 | 11 | `TGLFontFile` |
| 11 | 4 | 표기 크기(22 / 24) |
| 15 | 4 | mult = 24 (글리프 행 수) |
| 0x13 | 18368 | 폭/플래그 표 (전부 0x01) |
| +18368 | 128 × 48 | 반각 글리프: 행당 2바이트(16px), MSB 우선 |
| 그 다음 | 18368 × 72 | 전각 글리프: 행당 3바이트(24px), 24행 |

검증: 19 + 18368 + 6144 + 18368×72 = 1,347,027.
전각 글리프 인덱스 = cp949 코드 − 0x8140 (EXE 0x414BE3, 코드에 0x7EC0 가산 후 16비트). 반각 인덱스 = ASCII 바이트.
구현: `core/pm3/tfn.{h,cpp}`, 확인용 `pm3_dump font <TFN> <out.ppm> <cp949 hex>`.
다음 단계: 대사 출력 오퍼(71/84/90/1d, 1c)와 입력 대기 오퍼(1f, 51, 41, 4c, 47)를 장면에 연결.

## 대사 연결 (SCENE 페이지)

- `EvxEvent::Text`(op 71/84/1d/90)를 추가. 장면용은 71(서술)·84(대사)만 사용하고, 1d(메뉴/디버그 `fwin Close Error`)·90은 제외.
- 71과 84는 같은 줄을 연달아 내보내므로(71 에코 → 84 표시) 같은 텍스트가 이어지면 하나로 합침. 96개 스크립트, 6794줄.
- `SceneStep`: 줄마다 그 시점의 배경/스프라이트/초상화 상태를 스냅샷. `evx_clean_text`: ESC 코드 처리
  (`ESC '/' N` 변수값 → `?` 자리표시, `ESC '['..ESC ']'` 강조 표시 제거, `ESC 's'NN` 제거).
- `fmlyname`/`frstname` 같은 이름 자리표시는 엔진이 플레이어 이름으로 치환 → 지금은 그대로 표시.
- 뷰어: SCENE 페이지가 줄 단위로 진행. 화면 가운데 탭 / Space / Enter = 다음 줄, 가운데 위쪽 20% 탭 / B = 배경 교체.
  FONT24.TFN이 없으면 글자 없이 기존처럼 동작.
- 확인: `pm3_dump dialog <dir> <SCRIPT>` (줄 목록), `pm3_dump dialog <dir> <SCRIPT> <n> out.ppm` (n번째 줄 합성).
- 143개 EVX 트레이스는 변경 전과 바이트 동일.
