# PM3 iOS – 부팅 7단계: 생일 입력에서 게임이 종료되던 문제 (2건 수정)

## 증상
실기(iOS 빌드)에서 NEW GAME → 이름 → 성 → **"딸의 생일"** 단계에서 "게임이 종료되었습니다. 앱을 다시 실행하세요." 표시.

## 재현
`tools/pm3_tapdrive.cpp`(신규): 브리지 API 로 터치 스크립트를 넣고 매 탭 뒤 프레임을 `/tmp/drv_N.ppm` 으로 저장.
`pm3_tapdrive <game> <save> "264,380,4;400,200,1;..."` (NEW GAME → 대사 12번 탭 → 이름 결정(536,385) → … → 월 선택(393,54) → 일 탭).
이 환경(리눅스)에서 **같은 위치에서 동일하게 재현**됨: `FF /7 unimplemented @0040000c` (게스트가 PE 헤더 0x40000C 로 점프).

## 원인과 수정
1. **스택 파괴 → 잘못된 반환 주소** (실제 종료 원인): `x86host.cpp` 의 힙이 해제 없는 범프 할당기였음. 게임은 큰 에셋을 계속 `LocalAlloc/LocalFree` 하므로 힙 포인터가 0x800000 에서 위로 자라 스크래치(0x1E00000)와 **스택(0x1F00000)을 덮어씀** (크래시 시점 esp=0x01effe88, 힙 사용 지점 0x01ee98b0, 스택 전체가 0).
   - 수정: 크기 클래스별 free-list(`release()`), `LocalFree/HeapFree/LocalReAlloc` 이 블록 반환, 재사용 블록은 0 으로 초기화(LMEM_ZEROINIT 동작 유지), 고갈 시 `[heap exhausted]` 로그.
2. **시작 시 경고창 "시스템 보존용 데이타에 쓰기를 할 수 없습니다"**: `GetDiskFreeSpaceA` 가 실패(0) 반환 → 성공(1)과 8섹터/512B/여유 1.6GB 로 응답.

## 결과 (이 환경)
- 생일 월/일 선택 → 달력 표시 → 혈액형 선택 → "아버지의 생일" 단계까지 정상 진행, 종료 없음 (프레임 확인).
- 이전엔 월 선택 직후 종료.

## 한계
- iOS 실기에서 재확인하지는 못함(이 환경은 리눅스). 힙 크기 자체(22MB)는 그대로이므로, 메모리를 더 쓰는 장면에서 `[heap exhausted]` 로그가 나오면 알려주세요.
- 이름/성 입력 화면은 한글 조합 자모 버튼을 눌러 입력하는 방식이며, 이번 재현에서는 자모 하나로 진행했음.

## 추가 수정 (딸 생일 · 아빠 생일 이후 구간)
생일/혈액형/직업/확인 화면까지 모두 통과 확인 후 이어서 진행하다 발견한 두 문제:
3. **오프닝 장면 직후 종료**: `CreateThread` 를 그 자리에서 동기 실행하는데, 로더 스레드(0x430E9E, 화면 한 장을 ABP 해제)가 중첩 호출 상한 2천만 스텝을 넘겨 "callback failed: step limit" → 게임 종료. 스레드 호출 상한을 20억 스텝으로 상향(`cg_limit`).
4. **힙 고갈**: 해제된 DirectDraw 서피스의 픽셀 메모리가 반환되지 않았음 → 서피스 COM 참조 카운트(AddRef/Release) 추적, 0 이 되면 힙에 반환. 게스트 메모리 64MB 중 힙을 0x800000~0x3D00000 로 확대(스택 0x3F00000, 스크래치 0x3E00000).
- 디버그 로그 추가: `PostQuitMessage`, `SendMessage(WM_CLOSE/SYSCOMMAND/DESTROY)`, 종료 시 마지막 호스트 호출 목록.

### 결과
NEW GAME → 이름 → 성 → 딸 생일 → 혈액형 → 아빠 생일 → 직업 → 확인 → 오프닝 장면 → **게임 본 화면(딸의 방, 일정/실행/쇼핑/갈아입기/대화/상태보기 메뉴, 3월 31일 0/192)** 까지 종료 없이 도달.
### 한계
- 동기 스레드 방식이라 오프닝 한 장면 로드 동안 화면이 잠시 멈춤(실기에선 수 초일 수 있음). 협력 스케줄링은 아직 미구현.
- 본 화면 이후(메뉴 조작·일정 진행·전투/시험 등)는 아직 검증 안 함. 오디오 미구현.
