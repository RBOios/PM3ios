# TFN 폰트와 대사 출력 정리

## 1. TFN 폰트 (FONT22.TFN / FONT24.TFN)

EXE 로더(0x41350E)와 글리프 출력 함수(0x414B25 반각, 0x414BE3 전각)를 분석해 확정했다. 두 파일 모두 1,347,027 바이트.

| 오프셋 | 크기 | 내용 |
|---|---|---|
| 0 | 11 | `TGLFontFile` |
| 11 | 4 | 표기 크기 (22 / 24) |
| 15 | 4 | mult = 24 (글리프 행 수) |
| 0x13 | 18368 | 폭/플래그 표 (전부 0x01) |
| 다음 | 128 × 48 | 반각 글리프: 행당 2바이트(16px), 24행, MSB 우선 |
| 다음 | 18368 × 72 | 전각 글리프: 행당 3바이트(24px), 24행, MSB 우선 |

- 크기 검증: 19 + 18368 + 6144 + 18368×72 = 1,347,027
- 전각 인덱스 = cp949 코드 − 0x8140 (EXE에서 코드에 0x7EC0을 더하고 16비트로 자름)
- 반각 인덱스 = ASCII 바이트 (0..127)
- 반각 글자는 16px 비트맵 중 12px만 진행폭으로 사용
- 구현: `core/pm3/tfn.{h,cpp}` (`Tfn::load`, `draw_text`, `draw_dialogue_box`)
- 확인: `pm3_dump font <TFN> out.ppm <cp949 hex>`

## 2. 대사 연결

- EVX 텍스트 오퍼: 71(서술), 84(대사, 첫 인자 = 창 번호), 1d(메뉴/디버그), 90
- 장면에는 71과 84만 사용. 같은 줄이 71 → 84로 연달아 나오므로 하나로 합침
- 규모: 스크립트 96개, 6794줄
- `SceneStep` = 텍스트 + 그 시점의 배경 / 스프라이트 / 초상화 상태
- ESC 코드: `ESC '/' N` 변수값(→ `?`), `ESC '[' … ESC ']'` 강조 표시(제거), `ESC 's'NN`(제거)
- 이름 자리표시(fmlyname/frstname/…2)는 뷰어에서 "성"/"이름"/"성2"/"이름2"로 치환(실제 게임은 플레이어 입력 이름). 엔진이 플레이어 이름으로 치환하는 자리

## 3. 뷰어 조작

- 가운데 탭 / Space / Enter: 다음 줄 (마지막 줄 다음은 처음으로)
- 가운데 위쪽 20% 탭 / B: 배경 교체
- 좌우 1/3 탭: 이전/다음 페이지, 위쪽 20%는 ±20
- `FONT24.TFN`이 없으면 글자 없이 기존처럼 동작

## 3-1. 입력/선택지 조사 결과와 자동 진행

- 이야기용 EN 스크립트에는 플레이어 선택지가 없고, 전부 `WAIT(n)` 타이머로 진행되는 선형 컷신이다 (예: EN021).
- 메뉴 문구(op 1d의 `ESC[NN…ESC]`)는 디버그/시스템 스크립트(BDYTEST, SECRET, _NAMEIN, _Z 등)에만 있다.
  op 1b(7인자)는 창 생성이며 선택지가 아님.
- op 1f(WAIT, 30분의 1초 단위)를 `EvxEvent::Wait`로 기록하고, 줄마다 다음 줄까지의 대기 합계를 `SceneStep::ticks`에 저장 (대부분 60~61틱 ≈ 2초).
- 뷰어: A 키 또는 화면 가운데 아래쪽 20% 탭 = 자동 진행 켜기/끄기. 다음 줄까지 시간 = max(ticks/30초, 1.5초) + 글자 수 × 60ms. HUD에 AUTO 표시.

## 4. 확인한 것과 못 한 것

- 143개 EVX 트레이스는 변경 전과 바이트 동일
- `pm3_dump dialog <dir> <SCRIPT> <n> out.ppm`으로 합성 결과 확인 (EN101 3번째 줄)
- iOS 앱 본체는 이 환경에 SDL2가 없어 구문 검사까지만 함

## 5. 남은 일

- 디버그/시스템 스크립트의 메뉴(op 1d 메뉴, 1b)와 입력 오퍼 51, 4c, 47
- 이름 자리표시 치환, 변수값 `ESC /N` 표시
- 초상화 가시성·Z 순서·이동 보간, 파티클 오퍼(11, 15–18, 1b–1d)
